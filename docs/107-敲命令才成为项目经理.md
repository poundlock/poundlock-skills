## 1. 探针

动代码之前，用真实会话把设计押的几条平台行为量出来。六项全部通过（仅 `-p` 下），五样工具 hook 都拦得住、会话里都有；计划的「Rulings 预置」最后一条不用动用，`BLOCKED_TOOLS` 照设计列全五样。

### 1.1 做法

- 探针目录在仓库之外（`C:\Users\user\AppData\Local\Temp\poundlock-probe-pm\`），每一场一个空的工作目录 `work/<场>`，不是 git 仓库。
- 探针插件 `probe` 只经 `--plugin-dir` 加载：命令 `probe:mark`（正文叫模型照参数做事，再回一行 `MARK-OK`，后面跟它在这一轮的附加上下文里看到的以 `PROBE-CTX` 开头的暗号，看不到写 `NO-CTX`）；
  命令 `probe:hidden`（frontmatter 带 `disable-model-invocation: true`，正文叫它回 `HIDDEN-OK`）；记录钩子 `log.mjs` 挂在 `SessionStart`、`UserPromptSubmit`、`UserPromptExpansion`、
  `PreToolUse`（matcher `*`）上，把原始 hook 输入追加进 `logs/<场>.jsonl`，stdout 一个字不写、永远 exit 0；拒绝钩子 `deny.mjs` 挂在 `PreToolUse`、matcher
  `Skill|SendMessage|ListAgents|EnterWorktree|Workflow`，环境变量 `PROBE_DENY=1` 时返回 `permissionDecision: "deny"`、理由 `PROBE-DENY-REASON: the probe hook refuses tool <名字>.`；
  上下文钩子 `ctx.mjs` 挂在 `UserPromptExpansion`，`PROBE_CTX=1` 时返回 `additionalContext: "The code word for this turn is PROBE-CTX-4417."`。两个开关都经 `--settings` 的 `env` 传，各场只开要的那一个。
- P6 另有一份副本 `plugin-agent`：多一个 agent `probe-agent` 和插件根的 `settings.json`（`{"agent": "probe:probe-agent"}`）。
- 公共参数：`--settings`（`env` 见上，`claudeMdExcludes` 排除本仓库、上一层与用户层的 `CLAUDE.md`）、`--setting-sources project`、`--strict-mcp-config`、`--model sonnet`、
  `--permission-mode acceptEdits`、`--debug-file`。
- **没用 `--bg`，改用 `-p`。** `--bg` 在这个版本上起不来：带 `bypassPermissions` 时要先在用户设置里接受一份声明（`--setting-sources project` 不读用户设置）；换成 `acceptEdits` 之后
  报「Workspace not trusted」，要先在那个目录里交互地接受一次信任——那会往 `~/.claude.json` 写信任记录，探针不该改用户的配置。`-p` 跳过信任对话。仓库 `CLAUDE.md` 说「用 `--bg`、不用 `-p`」
  是因为 `-p` 下异步派发卡死过，这六项都不派发。一场里要接着说好几句的（P5）用 `-p --input-format stream-json --output-format stream-json`，一个进程里一句一句送，等到上一句的 `result` 再送下一句。
  `--resume` 照样要再带 `--plugin-dir`。
- 会话 id、转录路径照原样记（转录路径里的本机用户名换成 `user`）。

### 1.3 P2：`PreToolUse` 拒不拒得掉那五样工具

**输入原文节选**：记录钩子收到五条 `PreToolUse`，`tool_name` 依次是 `Skill`、`ListAgents`、`SendMessage`、`EnterWorktree`、`Workflow`（中间夹一条 `ToolSearch`，`select:SendMessage,EnterWorktree`），

### 1.4 P3：模型调命令时发不发 `UserPromptExpansion`；`disable-model-invocation`

**怎么量**：
- A（会话 `67838eb4-8ab5-4538-aa81-dfb2e0108261`，`PROBE_DENY=0`）：叫模型用 `Skill` 工具调 `probe:mark`，再调 `probe:hidden`，报两次的结果原文。
- B（会话 `ff1f1fa4-a9c3-4ef5-9912-8936e9faeec0`）：用户直接敲 `/probe:hidden`。

**输入原文节选**：A 的记录只有 `SessionStart`、`UserPromptSubmit`（prompt 是那段自然语言）和**一条** `PreToolUse`（`tool_name: "Skill"`，调 `probe:mark` 那一次），**没有 `UserPromptExpansion`**。
转录：

### 1.6 P5：压缩、续会话、`/clear` 前后的会话 id

**怎么量**：一个 `-p --input-format stream-json` 进程里依次送 `/probe:mark`、`/compact`、`/probe:mark`、`/clear`、`/probe:mark`；之后另起 `-p --resume <最初的 id> "/probe:mark"`，
再起一次加 `--fork-session` 的。第一次送的时候 Git Bash 把 `/compact` 改写成了 `C:/Program Files/Git/compact`（作为普通文字送了进去，那一场作废），设 `MSYS_NO_PATHCONV=1` 重跑。

**输入原文节选**（按到达顺序，只列 `session_id` 与要紧的键）：

## 2. 裁定

这一轮改的是一件事：插件根的 `settings.json` 删了，新开的会话是普通会话；用户在会话里敲 `/poundlock:at`、`at-tweak`、`at-resume`、`at-init`、
`at-skills` 之一，门禁按会话 id 给它**记号**（项目一级的门禁专属文件 `.poundlock/pm-sessions.json` 里的一条），这个会话才是**项目经理会话**，
到会话结束或 `/clear` 为止。**团队之外的人**指三种调用者：没记号的普通会话的主线程、身份被换成花名册外 agent 的主会话（设置里的 `agent` 键或别的 `--agent`）、
花名册外的子代理；三种同一个口径。下面每条写结论与理由；来历在设计（`docs/superpowers/specs/2026-11-27-跑命令才成为项目经理-design.md`）
与计划里。

### 2.1 设计时定的（设计 §8）

1. **项目经理会话里只拦绕得开门禁的那几样工具**：`Skill`、`SendMessage`、`ListAgents`、`EnterWorktree`、`Workflow`。MCP、网页搜索与抓取、宿主应用自带的工具不拦。
   理由：这几样能不经 `Agent` 起或续子代理、或者换工作树，派发白名单看不见；别的工具今天项目经理拿不到，只是 `tools:` 清单的副作用，不是目的，
   桌面应用的系统提示还要每个会话用它自带的工具，拦了每一轮都撞。门禁管的是派发与写入，不靠这块工具面。
2. **触发的是五条干活的命令**，`/poundlock:at-status` 只读、不触发；不另设一条专门的命令。理由：用户本来就要敲这几条，多一条命令多一步。
3. **没有变回普通会话的命令**。要普通会话就新开一个或 `/clear`。理由：记号跟着会话 id 走，`/clear` 换 id、对话也清空，两头对得上；一个会话中途变回去，
   对话里留着的角色正文就成了没人管的指令。
4. **团队之外的人用 `Edit` / `Write` 写不了 `.poundlock/` 下的任何东西**，`.poundlock/` 之外不拦。理由：团队的状态都在那里；普通会话的正常工作在别处。
5. **普通会话不受微调认领的约束**：改到微调正在改的文件，门禁不拦也不记。理由：今天按认领拦的只有带 `agent_id` 的写入，普通会话的主线程本来拦不到，
   让它的子代理被拦而主线程不被拦，两头不一致；用 `Bash` 改的文件门禁本来也不记。登在 §3。
6. **团队之外的调用者一律派不了团队角色**。理由：以前启用插件的目录里主会话都是项目经理，花名册外的调用者派团队角色这条路几乎够不着；普通会话成了常态，
   它够得着了。
7. **`agents/at-pm.md` 这个定义与「带它起的会话就是项目经理」留着**（`--agent poundlock:at-pm`）。续上之后身份没恢复的，敲一次 `/poundlock:at-resume`，
   不加新的身份来源。理由：命令行用户可以拿到平台锁住工具面的项目经理；升级之前开着的项目经理会话靠它不被改判（§1.7 量到续上之后照旧带 `agent_type`）。
8. **两种判不出来，方向相反**：hook 输入里没有会话 id 时当项目经理会话；记号文件读不出来时谁都不靠记号当项目经理（理由见 §2.3 第 1 条）。
   没有会话 id 当项目经理，是因为那种宿主上分不出会话、记号用不上，而输入是平台给的，会话里的模型改不了它。
9. **每一轮的自检提醒仍然不走 node**，措辞改成有条件的（只对项目经理会话说话）。理由：它不走 node，为的是 node 缺失、门禁全部失效时照样出现；
   要按记号决定出不出，就得走 node，正好在最需要它的时候没了。代价是普通会话每一轮多一行可以忽略的话。
10. **记号放在 `.poundlock/` 下**，命令展开时目录不在就建。理由：`/poundlock:at-init` 是一个项目的第一条命令，那时就要认得出项目经理。
11. **六条团队命令都不让模型自己调**（frontmatter `disable-model-invocation: true`），为它在 frontmatter 的受限写法里开第二个窄口。理由：模型经 `Skill`
    调命令不发 `UserPromptExpansion`、记不上号（§1.4），普通会话的上下文里也就不再列着团队命令；就算调起来，没有记号，第一次自检就被拒。
12. **Claude Code 的下限抬到做这轮实测的版本**（2.1.325，§1）。理由：成为项目经理整个押在 `UserPromptExpansion` 上，这个事件在原来的下限上没量过，
    那份旧版本也找不回来了；以前它不发只是少核一项，现在是敲了命令也成不了项目经理。版本不够时不静默：没记上号，第一次自检被拒，理由里提到可能是版本太旧。

### 2.2 计划里预先定的

1. **界面上那一行改由项目经理说。** `UserPromptExpansion` 上门禁的出口不发 `systemMessage`（`hooks/lib/fail-open.mjs` 的 `hookOutput` 的既有契约），
   所以记录器发一段受信回传【身份】，命令开头叫项目经理照它对用户说一句。
2. **`settings.json` 删掉，不留空对象。** 判据钉「文件不在」，免得有人把 `agent` 悄悄加回去。
3. **带 `agent_type` 的会话敲命令不记号。** 那种会话的身份由 `agent_type` 定。
4. **记号文件读不出来时，记录器把它重建成只有这个会话的一份**，stderr 留一行。理由：读不出来时谁都不是项目经理（§2.1 第 8 条），不重建就没有会话当得上；
   别的项目经理会话的记号已经随那份坏文件没了，它们下一次团队动作被拒、重新敲命令。
5. **命令每次展开都发【身份】**，不只第一次。理由：`/poundlock:at-resume` 正是压缩之后用的，那时要重新指到角色正文。「对用户说一句」只在第一次记号时带。
6. **拦的工具清单写两份、判据对齐。** `hooks/lib/checks.mjs` 被 `boot.mjs` 读、不能 import，`hooks/lib/pm-session.mjs` 的 `BLOCKED_TOOLS` 是单一真源，
   `checks.mjs` 里那份字面量由判据钉成相等。
7. **探针量出某样工具拦不住、或者会话里没有它，就从清单里去掉并登进开放边界**；量出普通会话主线程带 `agent_type` 或不带会话 id，就停下回报。
   §1 量下来两种情形都没有，五样照设计列全，设计的前提成立。

### 2.3 实现中定的

1. **记号文件读不出来时的方向反过来**（设计 §5.7 的修订）：原来定的是当项目经理，为的是「不让项目经理的门禁静默失效」。提交后的安全审查指出，
   文件读不出来就把每个普通会话当项目经理，等于把写契约、写门禁专属文件的权限给了从没敲过命令的会话，而这份文件用 `Bash` 就改得坏。
   反过来判并不静默：没了记号的项目经理下一次自检、派团队角色、写账本都被拒并拿到出路，和「记号丢了」是同一条大声拒的路；普通会话也不因为一份坏文件被拦。
   代价：文件坏了的那段时间里，原来的项目经理会话写不了账本、派不了团队角色，要用户重新敲命令。
   - 补（2026-11-28 终审后）：代价不止这些。文件坏着的那段时间里，原来的项目经理会话调 `Skill`、`SendMessage`、`ListAgents`、`EnterWorktree`、`Workflow`
     也不被拦（`pm-tools` 只拦项目经理），完成核验与两个批准记录器对它不出声、不记（它按团队之外的人分流）；它要到下一次自检、派团队角色或写 `.poundlock/`
     才知道自己没了记号。`tests/gate-pm-tools.test.mjs` 钉着「读不出来时五样放行」这一格。
2. **「`.poundlock/` 之下」按路径的每一段认，段名先规范化再比**：截掉冒号之后的流后缀、去掉结尾的点与空格、转小写；字面路径与解析过链接的物理路径
   任一命中都算。理由：Windows 上 `.poundlock.`、`.poundlock::$INDEX_ALLOCATION` 指向的是同一个目录，不规范化就认不出（安全审查提出）。
   **没有照审查建议把一切认不出的写法、网络路径对团队之外的人一律拒**：那会让放在网络共享上的项目里，普通会话连本地盘都写不了；网络路径、设备路径里
   带着 `.poundlock` 这一段的照样认得出。认不出的只剩共享或设备直接挂在 `.poundlock/` 里面的情形，要先有人建出那样的映射，登在 §3。
3. **`Bash` 改得了记号文件，不改。** 一个会话可以用 `Bash` 给自己记号、抹掉别人的记号。门禁不看 `Bash` 是仓库的长期决定（命令行是自由文本，判不准；
   权限模式才是那一层），README 写着这不是沙箱，批准记录、归属记录是同一个边界；把文件放到项目外或加签名都挡不住同一个用户的 `Bash`。
   会话 id 不进任何给模型看的文字，算一点摩擦。登在 §3。
4. **记号文件原子写**：写临时文件再改名盖过去。理由：先截断再写的话，写到一半崩掉会留下一份坏文件，下一次读成「读不出来」，真的项目经理被当成
   团队之外的人、别的会话的记号随重建丢掉（两次审查都提了）。
5. **门禁拼进文案的插件路径一律写成正斜杠**（反斜杠折成 `/`）。理由：判据与文案在各平台上同一个样子；Windows 上 `Read` 照样认正斜杠路径。
6. **`scripts/lib/version-bump.mjs` 的 `PLUGIN_LOADED` 仍列着插件根的 `settings.json`**，虽然文件已经删了。理由：有人加回来时它仍算插件会加载的、要挪中间一位。
7. **探针用 `-p` 代替 `--bg`**：`--bg` 在 2.1.325 上要先在用户设置里接受一份声明、或者在探针目录里交互地接受信任，两样都会改用户的配置（§1.1）。
   这几项都不派发，`-p` 下异步派发卡死过的那条老毛病碰不到。代价：交互会话与桌面应用里的行为没量，登在 §1.9 与 §4。
8. **压缩之后由门禁要求重读角色正文，不靠模型自己判断**（§5.5 之后加）：原来自检的拒绝理由末尾只说「眼前没有它的全文就先读它」，真实会话里压缩之后
   模型把压缩摘要当成了角色正文，没有去读。现在上下文压缩时平台发的 `SessionStart`（来源 `compact`，会话 id 不变，§1.6）上，新的检查项 `pm-compact`
   给记过号的会话在记号文件里记一个 `"reread": true`；带着它的会话下一次门禁自检，拒绝理由里那一句换成不带条件的「上下文压缩过……现在先读全文再做别的」，
   说过这一次就清掉标记（去掉这个键，不写 `false`）。没记过号的会话、带身份的会话（角色正文在系统提示里，压缩不丢）、记号文件读不出来时不记，也不重建
   （重建是敲命令的记录器的事）。标记只影响自检那一句话，派发、写文件、拦工具的判定一个字不变。**门禁不核模型读没读**：读没读没有可靠的信号，
   这一步只把「要不要读」从模型的判断换成门禁的判断。清标记写不进只在 stderr 留一行，自检照样拒、照样带「在线」、照样说那一句。
9. **带 `agent_id`、不带 `agent_type` 的调用者按所在会话的记号认**（2026-11-28 终审后定）：会话记过号、或者没有会话 id，照旧交给原来的代码
   （`{ outsider: false, pm: false }`：它的 `agent_id` 说明它不是主线程本身）；没记号是团队之外的人（`kind: 'subagent'`），记号文件读不出来时同样，
   另带「读不出记号文件」那一句。`hooks/gate.mjs` 的 `standingFor` 最后一层兜底同一个口径。理由：`docs/22` 量过，CLI 的内部分叉带的是主线程的
   `agent_type` 加它自己的 `agent_id`；主线程不带 `agent_type` 之后，普通会话的分叉正是这个形状。原来这一格不看记号、走原来的代码，终审用真实门禁子进程量到：
   没记号的会话里这种调用者写得进 `.poundlock/project.json`、派得出 `at-product`，等于拿到项目经理的权限——这是唯一一处不经记号的「不带 `agent_type`
   就是项目经理」。记过号的项目经理会话、带 `at-pm` 身份的会话、团队角色、没有会话 id 的宿主，判定一个字不变。这种形状会不会出现在 `PreToolUse` 上没量过，登在 §3。

## 3. 仍然开着的边界

1. **共享或设备直接挂在 `.poundlock/` 里面时，团队之外的人经它写进去，门禁认不出**：网络路径、设备路径里不带 `.poundlock` 这一段，规范化也认不出（§2.3 第 2 条）。
   要先有人建出那样的映射。
   - 订正（2026-11-28 终审）：认不出的不止「挂在 `.poundlock/` 里面」那一种。网络路径下 `norm()` 只做字面规范化、不解析链接与 8.3 短名，所以网络路径加短名
     （`\\localhost\C$\…\POUNDL~1\…`）、共享上的链接，团队之外的人经它写进 `.poundlock/` 也认不出；本地盘上的短名与链接认得出（物理路径那一路）。
2. **记号文件用 `Bash` 改得了**：一个会话可以给自己记号、抹掉别人的记号；与别的门禁专属文件（批准记录、归属记录）同一个边界（§2.3 第 3 条）。
3. **普通会话改到微调认领的文件，门禁不拦也不记**（§2.1 第 5 条，有意）。
4. **项目经理会话里拦的工具清单不封闭**：今天是 `Skill`、`SendMessage`、`ListAgents`、`EnterWorktree`、`Workflow` 五样；平台以后加了别的能绕开派发门禁起子代理的工具，
   门禁不会自己知道。
5. **`Bash` 改 `.poundlock/` 下的文件，对谁都拦不住**：团队之外的人也一样（与 `docs/00-开放边界.md` §2「`Bash` 不经门禁」同一族）。
6. **角色正文在对话里、不在系统提示里**：就地成为项目经理的会话，角色正文是命令开头读进来的；压缩之后靠每轮的提醒与自检回答里的路径重新去读。
   守纪律的程度没在真实会话里量过。
   - 订正（同日，§5.5）：`-p` 下量了一个会话里的两轮（压缩之后说「继续」、换进程续上再说「继续」）：两轮都先自检、拿到了带角色正文路径的拒绝理由，
     都**没有**再读角色正文，凭压缩摘要接着推进。门禁这一侧没错（每次都给了路径），靠的是模型的纪律；样本是一个会话、两轮，两轮都没守。仍然开着。
   - 订正（压缩之后那一句，§2.3 第 8 条）：压缩之后的第一次自检，那一句已经改成门禁判、不带条件（`pm-compact` 在压缩时给会话记标记，自检说一次就清）；
     不再靠模型自己判断「眼前有没有」。**仍然开着的**有两处：一轮当中自动压缩，到下一次自检之间的空档（这一轮后面的动作不一定先自检）；
     模型读了之后守不守，没量过（门禁不核读没读，真实会话里重新量这一步另有安排）。
   - 订正（重量，§5.5.1）：加了这一句之后在 `-p` 下重量，一个会话压缩两次，两次项目经理都在自检之后、别的团队动作（写 `state.json`、派人）之前读了角色正文全文。
     压缩之后这一格现在由门禁判、量过是守的。**仍然开着的**只剩：一轮当中自动压缩、到下一次自检之间的空档；样本小（一个会话、两次手动 `/compact`、只在 `-p` 下）。
7. **花名册读坏（插件装坏）时，没记号的主线程走原来的代码、被当成项目经理的口径**：身份判定在花名册读不出时不表态，主线程落进原来「不带 `agent_type`
   的主线程就是项目经理」的那一支——写得了 `.poundlock/`、账本对它说话；那时派发白名单对谁都拒。
8. **`tests/trusted-echo.test.mjs` 的 unknown-stage 入口现在只断言「不出声」**：团队之外的人分流在前、喂不到那个载荷，原来「去掉那处 `inline` 就红」的变异检测没了。
   - 收口（2026-11-28 终审后）：补了一个场景，hook 输入的 `agent_type` 是数组（认不出的调用者不归团队之外的人，交给原来的代码），照样走到 unknown-stage
     那一行、载荷进 stderr；把那一处的 `inline` 去掉，这个场景红（变异验证过）。
9. **记号文件的临时文件**：写临时文件那一步在出错处理之外，写到一半出错会留下 `.tmp`。只会累积，不会被读成记号。
   - 收口（2026-11-28 终审后）：写临时文件挪进了出错处理，写到一半抛错同样删掉临时文件再抛（`tests/gate-pm-compact.test.mjs` 用注入的 `write-partial` 钉着）。
10. **记号只增不减**：会话结束、`/clear` 都不撤它那一条，文件跟着用过的会话一直长；同一个会话 id 续上照旧是项目经理（有意）。
11. **Windows 上改名盖过正被读的记号文件**理论上可能报 EPERM / EBUSY：那时走「没有记成」，stderr 留一行、要用户再敲一次，不放行。
12. **带 `agent_id`、不带 `agent_type` 的调用者会不会出现在 `PreToolUse` 上，没量过**（§2.3 第 9 条）：`docs/22` 只在 `SubagentStop` 上量到这种形状。
   门禁现在按所在会话的记号认它，出现与否都不放权；量到了也只是确认这一格真有人走。
13. **花名册外的子代理停下时，`stop-gate` 与 `handback` 仍读运行上下文、往 stderr 留一行**：与设计 §5.4 表里「不出声」差一点。有意留着：这两项不拦
    花名册外的调用者任何东西，stderr 不进模型的对话，只在调试日志与留痕里看得到；把它们也接进团队之外的人的分流，要在 `SubagentStop` 与交回这两条
    最容易误拦的路上再加一个出口，换来的只是少一行没人读的痕迹。
14. **普通会话经一个声明了 `context: fork`、带 `agent:` 的 skill，能不经 `Agent` 起团队角色**：`Skill` 只在项目经理会话里拦，普通会话调得到用户或项目层的
    skill；那样起的子代理带团队角色的 `agent_type` 与自己的 `agent_id`，门禁把它当团队角色。插件自带的 skill 不声明 `context: fork`，挡不住别人写的。
15. **普通会话先 `EnterWorktree` 再敲团队命令，项目经理就在那个工作树里**：`EnterWorktree` 只在项目经理会话里拦，敲命令之前切过去的不拦；
    之后团队的活都在工作树里干，门禁按那时的 cwd 找项目根。项目根落在哪、跟原来的 run 对不对得上，没量过。

## 4. 没量到的

§1.9 已登的照旧开着。§5 这一轮真实会话全在 `-p`（SDK 宿主，stream-json）下量，下面这些没量到。

### 4.1 桌面应用里要用户自己走的一场

`--bg` 起不来（§1.1），桌面应用也驱动不了，这一场只能由用户在桌面应用里走。项目用一个很小的、不要紧的目录（一个 README、一两个源文件），
插件经 `--plugin-dir` 或本地克隆加载（README「安装」里「不安装，直接从本地克隆加载」那一段）。每一步写着做什么、看到什么算对：

1. **新开一个会话**，先不敲任何团队命令，叫它「派一个 Explore 看看有哪些文件」「建一个 notes.txt 写 hello」「用 Skill 调一个随便哪个 skill」。
   对：三样都做成；界面上没有 poundlock 的拒绝或说明，只有每轮那一行英文提醒（看得见的话），模型不照它做自检。顺带记：提醒在界面上显不显示、
   显示成什么样；模型有没有对用户提起这行提醒（§5.2 在 `-p` 下提了一句）。
2. **还是普通会话**：叫它写 `.poundlock/current-run`。对：被拒，理由以「poundlock：这个会话不是项目经理会话」开头、叫用户自己敲团队命令；
   模型照实转告，不换办法绕。
3. **敲命令**：同一个会话里敲 `/poundlock:at-init`（首跑会用 `AskUserQuestion` 问要不要把 `.poundlock/` 加进 `.gitignore`，照常选）。
   对：项目经理第一句就对用户说「这个会话从现在起是项目经理会话，到会话结束或 `/clear` 为止」；自检拿到「在线」；
   `.poundlock/pm-sessions.json` 里出现这个会话的 id（`command` 是 `at-init`）。顺带记：命令展开时的【身份】回传在界面上显不显示。
4. **成为项目经理之后**：敲 `/poundlock:at <两三句的小需求>`，走到派出 `at-product`。再叫它「用 Skill 调一个 skill」「派一个 general-purpose」。
   对：自检在线、派出了 `at-product`；`Skill` 被拒（「团队的会话里不开放 Skill 工具」）、`general-purpose` 被派发白名单拒，它不绕路。
   顺带记：桌面应用里工具面有没有 `SendMessage`、`ListAgents`、`EnterWorktree`、`Workflow`，有的话叫它各调一次，看是不是都被拒（§1.9）。
5. **压缩**：在界面上 `/compact`（有自动压缩的话也记一次）。对：会话 id 不变（侧边栏里还是同一个会话），之后的团队动作照旧被当成项目经理。
6. **继续**：说「继续」。对：它先自检，读角色正文（`at-pm.md`，路径是自检拒绝理由末尾给的那一个），再接着推进。
   §5.5 在 `-p` 下两次都没读角色正文，加了压缩后由门禁要求重读之后 §5.5.1 两次都读了；桌面应用里这一步仍是这一场最要看的，

### 4.2 交互会话里的各项（这一轮只能用 `-p`）

- 交互模式下 Agent 一律后台派发；`-p` 下 `at-product` 是前台派的，压缩之后的三次（两次 `at-architect`、一次 `at-qa`）没带 `run_in_background: false`、是后台派的（§5.5），两种都只在 SDK 宿主里见过。

### 5.2 Step 1：普通会话

### 5.7 Step 6：另开一个普通会话

**怎么量**：会话 A 的进程还开着、那一趟 run 没收口（停在 S3）的时候，在同一个 `proj` 里起会话 B，不敲团队命令，一句话叫它依次写 `scratch.txt`、派 `Explore` 看 `src/`、
写 `.poundlock/current-run`，每样只试一次、不换办法。

**看到的**：`scratch.txt` 写成（留痕 `writepath`、`contract`、`rework`、`ledger` 都放行）；`Explore` 派成、交回一句话（`delegation`、`readiness`、`stop-gate`、`deliverable` 都放行，
子代理停下时这次没有 H5b 的那行说明）；写 `.poundlock/current-run` 被拒：

```
PreToolUse:Write hook error: poundlock：这个会话不是项目经理会话。写这个文件被拒绝：团队的派发与对 .poundlock 的写入只属于项目经理会话。这一步模型自己做不了：请用户在这个会话里自己敲 `/poundlock:at <需求>`（也可以是 `/poundlock:at-tweak`、`/poundlock:at-resume`、`/poundlock:at-init`、`/poundlock:at-skills`），敲过之后这个会话才是项目经理会话。用户说已经敲过、你还是看到这一句，可能是 Claude Code 版本太旧或记号文件被删了，请用户再敲一次。
```

它原样转告，没有重试。这个会话里 hook 有输出的只有每轮那一行提醒、上面那一次拒绝和留痕。`current-run` 的内容没变（仍是 A 的 run id）。

**结论：通过。** 前两样不被拦，写 `.poundlock/current-run` 被拒。

### 5.8 这一轮没发现实现的缺陷

六步里门禁该放的都放了、该拒的都拒了，拒绝理由与回传都是设计里的那几句。没通过的只有 §5.5 的第一轮；原因在模型不按拒绝理由去读角色正文、不在门禁，
这是推断（门禁的每一次输出都核过，模型为什么不读没有直接证据）。之后加了压缩时由门禁要求重读（§2.3 第 8 条），重量两次都通过（§5.5.1）。
其余要记的模型行为：普通会话对用户提了一句提醒（§5.2）；`/poundlock:at` 带着够清楚的参数时项目经理不问需求稿、直接建 run（§5.3）；
【身份】不带「对用户说一句」时项目经理照样又说一遍（§5.6）。
