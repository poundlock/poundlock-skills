**日期**：2026-11-28　**CLI**：2.1.325（`claude --version` 输出 `2.1.325 (Claude Code)`）　**设计**：`docs/superpowers/specs/2026-11-27-跑命令才成为项目经理-design.md`（§3、§7 第 1～5、9 条）　**计划**：`docs/superpowers/plans/2026-11-27-跑命令才成为项目经理.md`（Task 0）

## 1. 探针

动代码之前，用真实会话把设计押的几条平台行为量出来。六项全部通过，五样工具 hook 都拦得住、会话里都有；计划的「Rulings 预置」最后一条不用动用，`BLOCKED_TOOLS` 照设计列全五样。

### 1.1 做法

- 探针目录在仓库之外（`C:\Users\user\AppData\Local\Temp\poundlock-probe-pm\`），每一场一个空的工作目录 `work/<场>`，不是 git 仓库。
- 探针插件 `probe` 只经 `--plugin-dir` 加载：命令 `probe:mark`（正文叫模型照参数做事，再回一行 `MARK-OK`，后面跟它在这一轮的附加上下文里看到的以 `PROBE-CTX` 开头的暗号，看不到写 `NO-CTX`）；
  命令 `probe:hidden`（frontmatter 带 `disable-model-invocation: true`，正文叫它回 `HIDDEN-OK`）；记录钩子 `log.mjs` 挂在 `SessionStart`、`UserPromptSubmit`、`UserPromptExpansion`、
  `PreToolUse`（matcher `*`）上，把原始 hook 输入追加进 `logs/<场>.jsonl`，stdout 一个字不写、永远 exit 0；拒绝钩子 `deny.mjs` 挂在 `PreToolUse`、matcher
  `Skill|SendMessage|ListAgents|EnterWorktree|Workflow`，环境变量 `PROBE_DENY=1` 时返回 `permissionDecision: "deny"`、理由 `PROBE-DENY-REASON: the probe hook refuses tool <名字>.`；
  上下文钩子 `ctx.mjs` 挂在 `UserPromptExpansion`，`PROBE_CTX=1` 时返回 `additionalContext: "The code word for this turn is PROBE-CTX-4417."`。两个开关都经 `--settings` 的 `env` 传，各场只开要的那一个。
- P6 另有一份副本 `plugin-agent`：多一个 agent `probe-agent` 和插件根的 `settings.json`（`{"agent": "probe:probe-agent"}`）。
- 公共参数：`--settings`（`env` 见上，`claudeMdExcludes` 排除本仓库、上一层与用户层的 `CLAUDE.md`）、`--setting-sources project`、`--strict-mcp-config`、`--model sonnet`、
  `--permission-mode acceptEdits`、`--debug-file`。
- **没用 `--bg`，改用 `-p`。** `--bg` 在这个版本上起不来：带 `bypassPermissions` 时要先在用户设置里接受一份声明（`--setting-sources project` 不读用户设置）；换成 `acceptEdits` 之后
  报「Workspace not trusted」，要先在那个目录里交互地接受一次信任——那会往 `~/.claude.json` 写信任记录，探针不该改用户的配置。`-p` 跳过信任对话。仓库 `CLAUDE.md` 说「用 `--bg`、不用 `-p`」
  是因为 `-p` 下异步派发卡死过，这六项都不派发。一场里要接着说好几句的（P5）用 `-p --input-format stream-json --output-format stream-json`，一个进程里一句一句送，等到上一句的 `result` 再送下一句。
  `--resume` 照样要再带 `--plugin-dir`。
- 会话 id、转录路径照原样记（转录路径里的本机用户名换成 `user`）。

### 1.2 P1：普通会话主线程的 hook 输入

**怎么量**：`-p "/probe:mark Use the Write tool to create a file named p1.txt in the current directory containing the word probe."`，同一轮里有命令展开和一次 `Write`。

**输入原文节选**（会话 `0d1e5ada-153c-4ab6-aaa4-87458681829c`，四条按到达顺序）：

```
SessionStart        {"session_id":"0d1e5ada-…","transcript_path":"C:\\Users\\user\\.claude\\projects\\…\\0d1e5ada-….jsonl","cwd":"…\\work\\p1","scratchpad_dir":"…","hook_event_name":"SessionStart","source":"startup"}
UserPromptSubmit    {"session_id":"0d1e5ada-…","transcript_path":"…","cwd":"…","scratchpad_dir":"…","prompt_id":"d5818557-38ad-476a-87bb-571377e8e8de","permission_mode":"acceptEdits","hook_event_name":"UserPromptSubmit","prompt":"/probe:mark Use the Write tool …"}
UserPromptExpansion {"session_id":"0d1e5ada-…","transcript_path":"…","cwd":"…","scratchpad_dir":"…","prompt_id":"d5818557-…","permission_mode":"acceptEdits","hook_event_name":"UserPromptExpansion","expansion_type":"slash_command","command_name":"probe:mark","command_args":"Use the Write tool …","command_source":"plugin","prompt":"/probe:mark Use the Write tool …"}
PreToolUse          {"session_id":"0d1e5ada-…","transcript_path":"…","cwd":"…","scratchpad_dir":"…","prompt_id":"d5818557-…","permission_mode":"acceptEdits","effort":{"level":"medium"},"hook_event_name":"PreToolUse","tool_name":"Write","tool_input":{"file_path":"…\\work\\p1\\p1.txt","content":"probe"},"tool_use_id":"toolu_01HuqRhtJbMoX7gSiGEWec3o"}
```

**结论：通过。** 四条都没有 `agent_type`（也没有 `agent_id`），都带同一个非空的 `session_id`。顺带量到的：`UserPromptSubmit` 先到、`UserPromptExpansion` 后到，两者 `prompt_id` 相同；
`command_name` 是带插件前缀的全名 `probe:mark`，参数在 `command_args`，`command_source` 是 `"plugin"`。

### 1.3 P2：`PreToolUse` 拒不拒得掉那五样工具

**怎么量**：`PROBE_DENY=1`，叫模型按顺序各调一次 `Skill`（`probe:mark`）、`SendMessage`、`ListAgents`、`EnterWorktree`、`Workflow`，延迟加载的先用 `ToolSearch` 取模式，不重试，最后报每一样拿到的原文。
会话 `b47febfd-823b-47e6-ab89-644f42eb6c13`。

**输入原文节选**：记录钩子收到五条 `PreToolUse`，`tool_name` 依次是 `Skill`、`ListAgents`、`SendMessage`、`EnterWorktree`、`Workflow`（中间夹一条 `ToolSearch`，`select:SendMessage,EnterWorktree`），
都没有 `agent_type`。例如：

```
PreToolUse {"session_id":"b47febfd-…","prompt_id":"f7b89680-a2f6-4a36-85c0-86ea1ffc0235","permission_mode":"acceptEdits","hook_event_name":"PreToolUse","tool_name":"SendMessage","tool_input":{"to":"nobody","summary":"ping","message":"ping","type":"message","recipient":"nobody","recipient_kind":"name","content":"ping"},"tool_use_id":"toolu_01BoSFn1KfWPLyo3oM2kbC73"}
```

转录里每一样的 `tool_result`（都是 `is_error`）：

| 工具 | 会话里有没有 | 模型拿到的原文 |
|---|---|---|
| `Skill` | 有 | `PreToolUse:Skill hook error: PROBE-DENY-REASON: the probe hook refuses tool Skill.` |
| `SendMessage` | 有（延迟加载） | `PROBE-DENY-REASON: the probe hook refuses tool SendMessage.` |
| `ListAgents` | 有 | `PreToolUse:ListAgents hook error: PROBE-DENY-REASON: the probe hook refuses tool ListAgents.` |
| `EnterWorktree` | 有（延迟加载） | `PreToolUse:EnterWorktree hook error: PROBE-DENY-REASON: the probe hook refuses tool EnterWorktree.` |
| `Workflow` | 有 | `PreToolUse:Workflow hook error: PROBE-DENY-REASON: the probe hook refuses tool Workflow.` |

**结论：通过。** 五样都被拒，模型拿到的都含拒绝理由原文，它在最后的回复里逐样照抄了，没有重试。`SendMessage` 的那一条前面没有 `PreToolUse:<名字> hook error:` 的前缀，只有理由本身；
别的四样有。拒绝理由的措辞不要依赖这个前缀。

### 1.4 P3：模型调命令时发不发 `UserPromptExpansion`；`disable-model-invocation`

**怎么量**：
- A（会话 `67838eb4-8ab5-4538-aa81-dfb2e0108261`，`PROBE_DENY=0`）：叫模型用 `Skill` 工具调 `probe:mark`，再调 `probe:hidden`，报两次的结果原文。
- B（会话 `ff1f1fa4-a9c3-4ef5-9912-8936e9faeec0`）：用户直接敲 `/probe:hidden`。

**输入原文节选**：A 的记录只有 `SessionStart`、`UserPromptSubmit`（prompt 是那段自然语言）和**一条** `PreToolUse`（`tool_name: "Skill"`，调 `probe:mark` 那一次），**没有 `UserPromptExpansion`**。
转录：

```
TOOL_USE Skill {"skill":"probe:mark"}
TOOL_RESULT "Launching skill: probe:mark"
TOOL_USE Skill {"skill":"probe:hidden"}
TOOL_RESULT (error) "<tool_use_error>Skill probe:hidden cannot be used with Skill tool due to disable-model-invocation. Ask the user to run /probe:hidden themselves — it cannot be invoked via the Skill tool. Do not replicate this skill's workflow by other means — it is reserved for explicit user invocation.</tool_use_error>"
```

会话开头的 `skill_listing` 附件里列着 `- probe:mark: Probe marker command`，没有 `probe:hidden`（P2 那场也一样）。B：

```
UserPromptSubmit    {"session_id":"ff1f1fa4-…","prompt":"/probe:hidden",…}
UserPromptExpansion {"session_id":"ff1f1fa4-…","expansion_type":"slash_command","command_name":"probe:hidden","command_args":"","command_source":"plugin","prompt":"/probe:hidden",…}
```

模型回 `HIDDEN-OK`。

**结论：通过。** 模型经 `Skill` 调起命令时不发 `UserPromptExpansion`；带 `disable-model-invocation: true` 的插件命令不出现在模型看得到的清单里，模型硬调被平台拒，
而且这次被拒的调用**不经过 `PreToolUse`**（记录钩子没收到它）；用户敲得动，照常发 `UserPromptExpansion`。

### 1.5 P4：`UserPromptExpansion` 的 `additionalContext` 模型看不看得到

**怎么量**：`PROBE_CTX=1`，敲 `/probe:mark`（会话 `236efb8e-583e-4db8-81aa-a4e7bddf91ff`）。

**输入原文节选**：记录钩子收到 `UserPromptExpansion`（`command_name: "probe:mark"`、`command_args: ""`）。转录里那一轮：

```
USER (meta) PROBE-MARK-BODY. Arguments: …
ATTACH {"type":"hook_additional_context","content":["The code word for this turn is PROBE-CTX-4417."],"hookName":"UserPromptExpansion","toolUseID":"hook-c4bf1fdf-…","hookEvent":"UserPromptExpansion"}
ASSISTANT MARK-OK PROBE-CTX-4417
```

**结论：通过。** 暗号只在这段附加上下文里出现过，模型在同一轮原样报了出来。没开 `PROBE_CTX` 的几场模型都回 `NO-CTX`。

### 1.6 P5：压缩、续会话、`/clear` 前后的会话 id

**怎么量**：一个 `-p --input-format stream-json` 进程里依次送 `/probe:mark`、`/compact`、`/probe:mark`、`/clear`、`/probe:mark`；之后另起 `-p --resume <最初的 id> "/probe:mark"`，
再起一次加 `--fork-session` 的。第一次送的时候 Git Bash 把 `/compact` 改写成了 `C:/Program Files/Git/compact`（作为普通文字送了进去，那一场作废），设 `MSYS_NO_PATHCONV=1` 重跑。

**输入原文节选**（按到达顺序，只列 `session_id` 与要紧的键）：

```
SessionStart        session_id fda96309-16f6-4da7-95b2-ed5fe94cd14c  source "startup"
UserPromptSubmit    fda96309-…  prompt "/probe:mark"
UserPromptExpansion fda96309-…  command_name "probe:mark"
SessionStart        fda96309-…  source "compact"        ← /compact
UserPromptSubmit    fda96309-…  prompt "/probe:mark"
UserPromptExpansion fda96309-…  command_name "probe:mark"
SessionStart        9d90d32c-db0d-4008-998f-4aa5934bf586  source "clear"   ← /clear
UserPromptSubmit    9d90d32c-…  prompt "/probe:mark"
UserPromptExpansion 9d90d32c-…  command_name "probe:mark"
--- 另起 -p --resume fda96309-… ---
SessionStart        fda96309-…  source "resume"
UserPromptSubmit    fda96309-…  prompt "/probe:mark"
UserPromptExpansion fda96309-…  command_name "probe:mark"
--- 另起 -p --resume fda96309-… --fork-session ---
SessionStart        9e243d25-0e1d-49a9-8d66-254156490336  source "fork"
UserPromptSubmit    9e243d25-…  prompt "/probe:mark"
UserPromptExpansion 9e243d25-…  command_name "probe:mark"
```

stream-json 每一句的 `result` 里的 `session_id` 与上面一致：`/clear` 那一句起变成 `9d90d32c-…`。

**结论：通过。** 压缩、`--resume` 之后 `session_id` 不变；`/clear` 与分叉之后换了一个新的。与 `docs/103` §8 第 4 条在 2.1.310 上量的一致。顺带量到的：`/compact`、`/clear`
这两条内建命令本身**不触发** `UserPromptSubmit` 和 `UserPromptExpansion`，只在之后发一条 `SessionStart`（`source` 分别是 `compact`、`clear`）。这一项量的是手动的 `/compact`，没量自动压缩。

### 1.7 P6：带 agent 起的会话，插件的 `settings.json` 没了以后续上

**怎么量**：用 `plugin-agent`（插件根 `settings.json` 指 `probe:probe-agent`）起会话 `df4bc833-4eed-4bcf-8202-a20a5c20b0dd`，敲 `/probe:mark` 叫它 `Write` 一个文件；进程结束后把
`settings.json` 挪出插件目录（agent 定义本身还在），再 `-p --resume df4bc833-… --plugin-dir <plugin-agent>`，敲同样的命令写另一个文件。

**输入原文节选**：

```
起会话：
SessionStart        {"session_id":"df4bc833-…","agent_type":"probe:probe-agent","hook_event_name":"SessionStart","source":"startup",…}
UserPromptSubmit    {"session_id":"df4bc833-…","agent_type":"probe:probe-agent",…}
UserPromptExpansion {"session_id":"df4bc833-…","agent_type":"probe:probe-agent","command_name":"probe:mark",…}
PreToolUse          {"session_id":"df4bc833-…","agent_type":"probe:probe-agent","tool_name":"Write",…}
删掉 settings.json 后续上：
SessionStart        {"session_id":"df4bc833-…","hook_event_name":"SessionStart","source":"resume","seconds_since_last_response":…,"context_tokens":…,…}   ← 没有 agent_type
UserPromptSubmit    {"session_id":"df4bc833-…","agent_type":"probe:probe-agent",…}
UserPromptExpansion {"session_id":"df4bc833-…","agent_type":"probe:probe-agent","command_name":"probe:mark",…}
PreToolUse          {"session_id":"df4bc833-…","agent_type":"probe:probe-agent","tool_name":"Write",…}
```

**结论：通过。** 续上的会话里 `UserPromptSubmit`、`UserPromptExpansion`、`PreToolUse` 仍带 `agent_type: "probe:probe-agent"`，平台恢复的是会话原来的 agent，不看现在的设置。
**唯一的例外是续上那一刻的 `SessionStart`（`source: "resume"`）不带 `agent_type`**——起会话那一刻的 `SessionStart` 带。要在 `SessionStart` 上认身份的，续上时认不出它是项目经理。

### 1.8 不通过项的处置

没有不通过的项。照计划「Rulings 预置」最后一条：五样工具 hook 都拦得住、会话里都有，`BLOCKED_TOOLS` 照设计列全 `Skill`、`SendMessage`、`ListAgents`、`EnterWorktree`、`Workflow`，
不用从里面去掉、不用在 `docs/00-开放边界.md` 为它记行；P1 成立，设计的前提在；P6 通过，不用走设计 §5.8 里「续上之后不带 `at-pm`」那一支。

给后面各任务的几条实测事实（不是不通过，但实现要照着）：
- 认身份不要放在 `SessionStart` 上：续会话那一刻它不带 `agent_type`（§1.7）。
- `/compact`、`/clear` 不发 `UserPromptSubmit` / `UserPromptExpansion`；压缩后要重新指到角色正文，只能靠之后的那几个事件或 `SessionStart`（`source: "compact"`）（§1.6）。
- 被 `disable-model-invocation` 挡下的 `Skill` 调用不经过 `PreToolUse`，`Skill` 检查项看不到它，也用不着看（§1.4）。
- `PreToolUse` 拒掉 `SendMessage` 时模型拿到的文字没有前缀，判据与文案别押前缀（§1.3）。

### 1.9 这一轮没量到的

- **`--bg` 与交互会话、桌面应用。** 这一轮全在 `-p`（含 stream-json）下量（§1.1 说了为什么）。交互模式、桌面应用里工具面可能不同（例如有没有 `Workflow`、`ListAgents`），
  五样工具在那里有没有、拦不拦得住，`UserPromptExpansion` 的附加上下文在界面上怎么显示，没量。设计 §7 第 7 条那一场桌面应用里的真实会话留给 Task 9。
- **自动压缩、桌面端重开会话**：只量了手动 `/compact` 与命令行 `--resume`，与 `docs/103` §6 的那一条同。
- **设计 §7 第 2 条里「这五条命令」**：这一轮只拿探针的命令量了 `UserPromptExpansion` 发不发、附加上下文到不到；poundlock 自己的五条命令要等命令改完再看。
- **P6 用的是探针 agent**，不是升级前真正的 `poundlock:at-pm` 会话；平台的行为是同一条（续上恢复原 agent），没有拿旧版插件起一个真的项目经理会话再升级续上。
