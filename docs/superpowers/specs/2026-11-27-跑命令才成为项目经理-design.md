# 跑命令才成为项目经理 —— 设计

**日期**：2026-11-27　**状态**：已批准（2026-11-27；审阅子代理提的四个问题、指出的四处与仓库对不上的地方，按「我的裁定」补进了正文）。2026-11-28 实现中修订了 §5.7：记号文件读不出来时的方向反过来（提交后的安全审查提出，理由写在那一节）　**来源**：与用户的头脑风暴（插件作者本人）；现行版本 9.1.0

---

## 1. 为什么要做

现在插件根的 `settings.json` 写着 `"agent": "poundlock:at-pm"`。在启用了插件的目录里，每一个新开的会话都是项目经理：
工具面只剩派发、提问、读写与 `Bash`，用不了 skill、MCP、网页搜索和浏览器。身份在会话启动那一刻定下，中途换不回来，
插件和 Wellyard 的 `--team` 也都只有开、没有关。

用户的话：「新开会话就是普通会话，然后我执行一个命令才变成项目经理会话」。

背后的情形（这一句是我的推断，不是用户原话）：一个启用了团队的目录里，多数会话是普通的活——上线、看页面、用别的插件的
skill；起一趟团队的 run 是少数。默认接管把多数会话都变成了少数那一种。

## 2. 目标、不做、反目标

**目标**

1. 启用了插件的目录里，新开的会话是普通会话：工具齐全，门禁不拦它的正常工作，也不往它的对话里加团队的话。
2. 用户在会话里敲一条团队命令，这个会话就成为项目经理会话：门禁从这一刻起把它当项目经理，角色说明到位。
3. 同一个目录里，项目经理会话和普通会话可以同时开着，互不影响。
4. 桌面应用里能用（桌面应用没有 `--agent`，也不能给单个会话传参数）。

**不做**

- 不做「变回普通会话」的命令。要普通会话就新开一个，或者 `/clear`（见 §5.2）。
- 不动团队角色（子代理）的工具面、阶段链、产物、契约、返工、微调这些机制。
- 不改 Wellyard `--team` 往线目录写的那三项设置，只改它文档里的说法。
- 不推广用户级安装。就地变身之后装成 user 作用域不再接管每个会话，但这一版不改安装方式。
- 不删 `agents/at-pm.md`，也不停掉「带 `at-pm` 身份起的会话就是项目经理」这条老路（见 §5.8）。

**反目标**（做成了也算失败）

- 普通会话的正常工作被门禁拦（派 `Explore`、`general-purpose` 这类子代理，写项目文件），或者对话里多出门禁的回传。
- 项目经理会话的记号丢了、读不出来时，门禁对它静默失效。丢了要大声拒。
- 压缩或续会话之后，项目经理不声不响地按普通会话行事。
- 升级之前开着的项目经理会话、进行中的 run，升级之后被改判。

## 3. 平台给的限制

2026-11-27 对着 Claude Code 官方文档查过，下面几条决定了能怎么做：

- **运行中的会话换不了主线程的 agent。** 没有这样的斜杠命令；命令与 skill 的 frontmatter 也改不了主会话余下时间的系统提示和
  工具面（`allowed-tools` 只是预先批准，`disallowed-tools` 到下一条消息就清）。
- **桌面应用没有按会话指定 agent 的入口。** 命令行有 `--agent`，续会话时也能带它；桌面应用没有。
- **续会话时恢复的是会话原来的 agent。** 文档说续上的会话保留原来的工具限制与模型；agent 不在了才退回默认工具并给一句警告。
- **hook 输入里的 `agent_type`，主线程只在会话带 agent 起的时候才有。** 普通会话的主线程没有它。
- **`PreToolUse` 的 hook 可以拒掉任意工具调用**，MCP 工具也能匹配到。`Skill` 工具能不能这样拒，文档没写。
- **`SessionStart`、`UserPromptExpansion` 的 hook 只能往对话里加上下文**，改不了身份、系统提示和工具面。

所以「变成项目经理」做不成换身份。能做的是两件事合起来：**门禁把这个会话记成项目经理会话**，**角色说明进到对话里**。

## 4. 考虑过的做法

- **A 就地变身（选了这个）**：插件不再默认接管；用户敲团队命令时门禁给这个会话记号，角色说明进对话；门禁只管记过号的会话和
  它派出去的角色。只有它在桌面应用里给得出用户要的效果。代价见 §5.5、§5.3：项目经理不再是平台层面的独立身份，
  工具面要靠门禁拦，角色说明在对话里而不在系统提示里。
- **B 预约下一个会话**：命令往目录的本地设置里写 `agent`，下一个新开的会话是真正的 `at-pm`，它一启动就把这一项撤掉。
  项目经理保持硬身份，门禁改得少。没选：是「跑命令再新开一个」两步，不是这个会话变；预约之后、新开之前别的新会话会被抢成
  项目经理；改设置那一刻对正在跑的会话有没有影响，文档没写，老版本上测到过会接管。
- **C 命令行起会话时带 `--agent poundlock:at-pm`**：改动最小。没选：桌面应用用不了。这条路留着（§5.8），只是不当主路。
- **目录级开关**（改 `enabledPlugins`）：给不了「默认普通、按会话变」；切的时候对在跑的会话有副作用。
- **命令的 frontmatter 自带 hook**（只在跑过命令的会话里挂门禁）：hook 没挂上时平台一律放行、不出声，续会话之后它还在不在
  文档没写。门禁不能押在这上面。

用户 2026-11-27 选了 A。

## 5. 设计

### 5.1 主线程的三种身份

门禁对**主线程**（hook 输入不带 `agent_id`）的调用，按下面的顺序认：

| 身份 | 怎么认 | 门禁怎么待它 |
|---|---|---|
| 项目经理会话 | `agent_type` 剥掉插件前缀是 `at-pm`；或者不带 `agent_type`、这个会话记过号（§5.2） | 和今天的主会话一样 |
| 普通会话 | 不带 `agent_type`，没记过号 | 当团队之外的人（§5.4） |
| 被换掉的主会话 | 带别的 `agent_type`，名字不在花名册里 | 当团队之外的人（§5.4），拒绝理由末尾照旧说身份 |
| 被换成别的团队角色的主会话 | 带花名册里别的角色的 `agent_type` | 和今天一样 |

今天的口径是「不带 `agent_type` 的主线程就是项目经理」。这次改的就是这一条：不带 `agent_type` 的主线程，记过号才是。

子代理（带 `agent_id`）怎么认不变：团队角色按派发记录认回派它的那一趟，花名册外的是团队之外的人。

下文的**团队之外的调用者**指三种：普通会话的主线程、被换掉的主会话、花名册外的子代理。三种同一个口径（§5.4）。

### 5.2 记号

- **是什么**：项目一级的一份门禁专属文件（建议 `.poundlock/pm-sessions.json`），按会话 id 记哪些会话是项目经理会话，
  每条带记下的时间和是哪条命令。任何人的 `Edit` / `Write` 都拒，和别的门禁专属文件一样登记在 `hooks/lib/control-files.mjs`。
- **谁记、什么时候记**：一个新的记录器，挂在 `UserPromptExpansion` 上。用户敲 `/poundlock:at`、`/poundlock:at-tweak`、
  `/poundlock:at-resume`、`/poundlock:at-init`、`/poundlock:at-skills` 时，给这个会话记号。`/poundlock:at-status` 只读，不记。
  已经记过的不重复记。
- **只认用户自己敲的命令。** 模型自己经 `Skill` 工具调起这几条命令不算（那一路不发 `UserPromptExpansion`，要实测）。
  六条命令的 frontmatter 都加 `disable-model-invocation: true`（对插件命令生不生效要实测）：模型调不起来，普通会话的
  上下文里也不再列着团队的命令——今天项目经理没有 `Skill` 工具，这件事不存在；普通会话有。就算调起来了，没有记号，
  第一次自检就被拒（§5.6）。这一行不在 frontmatter 的受限写法里（布尔值今天只有逐字的 `omitClaudeMd: true` 一个窄口），
  要在 `tests/frontmatter-subset.test.mjs` 开第二个窄口，仓库 `CLAUDE.md` 里那条决定的说法跟着改。
- **`.poundlock/` 还不在时**：记录器建出这个目录再记。`/poundlock:at-init` 是一个项目的第一条命令，那时候就得认得出项目经理。
- **用户看到什么**：第一次记号的那一刻，界面上一行固定的话，说这个会话从现在起是项目经理会话。
- **记号跟着会话 id 走**：压缩、续会话不换 id，记号还在。`/clear` 和分叉出去的会话换了 id，没有记号，是普通会话——
  `/clear` 之后对话也清空了，两头对得上。清空之后要接着跑那一趟，敲 `/poundlock:at-resume`：重新记号，再走现有的接手。
- **不做变回去**：记过号的会话到结束都是项目经理会话。

记录器和别的记录器一样：不拦任何东西（这个事件上 exit 2 会把用户的命令拦掉），记不下就留痕；记不下的后果是这个会话
没成为项目经理，第一次自检会拒并说明（§5.6），不是静默失效。

### 5.3 角色说明怎么到位

角色正文的单一真源仍是 `agents/at-pm.md` 的正文。今天它是主会话的系统提示；就地变身之后，会话的系统提示是 Claude Code
默认的那一份，角色正文要进到对话里。要求：

1. 变身的那一轮，模型做第一件事之前已经拿到角色正文全文。
2. 压缩之后、续会话之后，不靠用户提醒就重新拿到。
3. 正文里的 `${CLAUDE_PLUGIN_ROOT}` 要是换好的路径。平台只在把文件当角色或命令加载时替换它；模型用 `Read` 直接读
   `agents/at-pm.md`，读到的是没换的字面，照着它找不到文件。
4. 角色正文里凡是以「主会话就是 `at-pm` 这个 agent」为前提的句子，照新情形改。

怎么送到留给实现者（命令正文开头叫它读并给出换好的根路径，或者由 hook 把换好的正文放进回传，或者两者都用）。

压缩与续会话那一头不能押在 `SessionStart` 上：仓库记着它在续会话时不再注入同样的文本，压缩之后注不注入没量过。
续会话时对话还在，角色正文也还在；要补的主要是压缩。载体用每一轮的自检提醒：它在每条用户消息上都出现，续会话、
压缩之后照样有。提醒里带上角色正文在哪（hook 的命令行里的 `${CLAUDE_PLUGIN_ROOT}` 平台会换好）和「眼前没有角色正文就
先读它」这一句。压缩之后这样够不够，要实测。

**每一轮的自检提醒**（`UserPromptSubmit` 上那一句不走 node 的 `echo`）保留不走 node，措辞改成有条件的：这个会话是
项目经理会话才照做，不是就忽略。理由：它故意不走 node，为的是 node 缺失、门禁全部失效时照样出现；要按记号决定出不出，
就得走 node，正好在最需要它的时候没了。代价是普通会话每一轮多一行可以忽略的话。

### 5.4 普通会话：团队之外的人

团队之外的调用者（§5.1 末尾那三种）同一个口径。这是一条**新的判定，不依赖运行上下文**：有没有 run、run 读不读得出、
开没开着微调，结果都一样。

| 门禁 | 团队之外的调用者 |
|---|---|
| 派发白名单 | 目标是花名册里的名字：拒，理由说这个会话不是项目经理会话、要用团队先敲哪条命令。别的目标（包括不写 `subagent_type`）：放行，不出声 |
| 就绪 | 不判 |
| 写路径、契约 | `.poundlock/` 之下的 `Edit` / `Write`：一律拒，理由末尾说出路。`.poundlock/` 之外：放行，不出声，不读运行上下文，不比微调的认领 |
| 推进、收口、建 run、返工预算 | 都发生在写 `state.json` 上，写不了它，够不着 |
| 账本回传、交付物校验、完成通知 | 不出声，不记账 |
| 批准记录器（提问作答、对话里单独发的规范标签） | 不记。只认项目经理会话 |

为什么要新写，不复用今天「花名册外的调用者」那一支。今天那一支看运行上下文，有三处对普通会话是错的：

- **还没有 run 时，写路径与契约两道门禁对谁都放行**（at-init 自举的既有设计）。花名册外的调用者写得成 `project.json`、
  建得出 `state.json`。就地变身之后自举由记过号的项目经理会话做，这条放行对团队之外的人不再需要。
- **run 读不出来时，非项目经理的每一次 `Edit` / `Write` 在看路径之前就拒**。建第一趟 run 的正路上就有这样一瞬间。
  普通会话写项目文件不该因为别的会话的 run 坏了而被拦。
- **开着微调时，带 `agent_id` 的非项目经理写被认领的文件会被拒**。普通会话的子代理会撞上，主线程不会，两头不一致。
  定成都不拦：普通会话改到微调正在改的文件，门禁不拦也不记，登记进开放边界（用 `Bash` 改的文件门禁本来也不记）。

团队角色（花名册里的名字）在这三种状态下照旧，不动。

**团队角色只能由团队派。** 团队之外的调用者派花名册里的角色，一律拒。今天花名册外的调用者派团队角色是放行的；以前启用
插件的目录里主会话都是项目经理、派不出花名册外的子代理，这条路几乎够不着。普通会话成了常态之后它够得着了，所以关上。

`Bash` 照旧没有门禁看着。普通会话用 `Bash` 改 `.poundlock/` 下的文件拦不住，这是摩擦，不是屏障，和今天对各角色的口径一样。

### 5.5 项目经理会话的工具

带 `at-pm` 身份起的会话，工具面照旧由 `agents/at-pm.md` 的 `tools:` 定。下面说的是就地变身的会话，它保留着普通会话的全部工具：

- **`Agent`**：派发白名单照旧，按花名册里主会话那一行判，只派得动那四个角色。
- **绕得开门禁的那几样工具：门禁拦。** 新加一个检查项，只拦项目经理会话主线程的调用。拦的是「不经 `Agent` 就能起、续
  子代理，或者换工作树」的工具，今天是这几样，清单是单一真源、不声称封闭，登记进开放边界：
  - `Skill`：`context: fork` 的 skill 能带着 `agent:` 直接起一个子代理，派发白名单看不到；superpowers 的 `SessionStart`
    注入出现在大多数项目经理转录里，今天项目经理没有 `Skill` 工具，无从照做，就地变身之后有了。理由里说出路
    （`/poundlock:at-skills` 登记）。
  - `SendMessage`、`ListAgents`：和 `Skill` 是同一条长期决定里的三样（任何角色都不授）。`SendMessage` 能续起已经停下的
    团队角色，不经 `Agent`，派发白名单、就绪、不记回退的重做都看不见。
  - `EnterWorktree`：门禁找项目根的前提是团队进不了 worktree。
  - `Workflow`（会话里有这个工具时）：它自己起子代理。
  hook 拦不拦得住这几样要逐个实测；拦不住的退回只靠角色正文，并在开放边界里登记。用户自己敲的别的插件的斜杠命令
  不经 `Skill` 工具，不拦，那是用户的意思。
- **MCP、网页搜索与抓取、宿主应用自带的工具：不拦。** 今天项目经理拿不到它们，是 `tools:` 清单的副作用，README 把它列在
  已知边界里，不是目的。桌面应用的系统提示要每个会话用它自带的工具（任务列表、收尾框这些），拦了每一轮都会撞。
  门禁管的是派发与写入，不靠这块工具面。

两个连带的后果，写进 README 和角色正文：

- 变身之前对话里已有的内容，都跟着进了项目经理会话。起一趟 run 最好在刚开的会话里敲命令。
- 项目经理现在看得了网页、用得了 MCP。角色正文补一句：这些只用来核实和回答用户，团队的活照旧派出去。

### 5.6 自检

项目经理的门禁自检（往 `.poundlock/gate-check` 写一句话，等门禁拒）不变，多一种结果：

- 项目经理会话：拒，理由含「门禁自检：在线」。和今天一样。
- 普通会话（没记号）：拒，理由说门禁在线、但这个会话不是项目经理会话，并给出路（让用户自己敲团队命令）。角色正文的
  自检一节加上这一支：停下，把原因告诉用户。

这也是记号丢了时的出口：项目经理下一次自检、派发或写账本就被拒，并拿到原因。

### 5.7 判不出来时

两种判不出来，方向相反（2026-11-28 修订，见本节末尾）：

- **hook 输入里没有会话 id**（旧的 Claude Code、别的宿主）：**当项目经理会话**，和这次改动之前一样。这种宿主上分不出会话，
  记号用不上；输入是平台给的，会话里的模型改不了它。
- **记号那份文件读不出来**（被改坏、截断、不是文件）：**谁都不靠记号当项目经理**，不带 `agent_type` 的主线程一律按团队之外的人待，
  拒绝理由里加一句说明原因与修法。用户重新敲一次团队命令，记录器把这份文件重建成只有这个会话的一份；别的项目经理会话
  下一次团队动作被拒，同样重新敲命令。
- 记号那份文件不存在，是「一个项目经理会话都没有」，不是读不出来。

修订的理由。原来两种都当项目经理，为的是「不让项目经理的门禁静默失效」。提交后的安全审查指出：文件读不出来就把每个
普通会话都当项目经理，等于把写契约、写控制文件的权限给了从没敲过命令的会话，而这份文件用 `Bash` 就改得坏。反过来判
并不会静默失效：没了记号的项目经理下一次自检、派团队角色、写账本都被拒并拿到出路，和「记号丢了」是同一条路（反目标
第二条要的正是大声拒）；普通会话也不会因为一份坏文件被拦（反目标第一条）。

`Bash` 改得了这份文件，所以一个会话可以给自己记号、抹掉别人的记号——这和别的门禁专属文件（批准记录、归属记录）是同一个
已知边界：门禁不看 `Bash`，README 写着这不是沙箱。记进开放边界；会话 id 不进任何给模型看的文字，算一点摩擦。

### 5.8 升级与旧状态

- **插件根的 `settings.json` 去掉 `agent`。** 升级之后新开的会话是普通会话。这是行为变化，写进 CHANGELOG。
- **升级之前开着的项目经理会话不被改判。** 续上之后平台恢复它的 `at-pm` 身份，门禁照旧按 `agent_type` 认它。配一条
  「上一版状态的夹具」判据：带 `agent_type` 为 `at-pm`、没有记号的主线程，照旧是项目经理。
  实测发现续上之后不带 `at-pm` 的话（§7 第 9 条），**不加新的身份来源**：那样的会话下一次团队动作会被拒并指到
  `/poundlock:at-resume`，敲了就记号；会话 id 没变，它还是那一趟的主人，接着跑。磁盘上那一趟怎么判没有变，多的是
  用户敲一条命令。这种情形下 CHANGELOG 与 README 的更新一节写明。
- **Claude Code 的下限抬到做这轮实测的那个版本**（或者实测到的更低版本）。变身整个押在 `UserPromptExpansion` 上，这个
  事件在现行下限上没量过，那份旧版本也找不回来了；以前它不发只是少核一项，现在是敲了命令也成不了项目经理。
  下限的真源在 `docs/00-现行参考.md`，README 两半、角色正文的排查清单与判据跟着改。版本不够时不是静默失效：
  没记上号，第一次自检被拒，理由里把「Claude Code 太旧」列为可能的原因之一。
- **命令行用户可以继续 `claude --agent poundlock:at-pm`**，拿到硬身份的项目经理。README 提一句，不当主路。
- **进行中的 run**：归属照旧按会话 id。新会话要接手，敲 `/poundlock:at-resume`，先记号、再走现有的接手。
- **模型**：就地变身的项目经理用这个会话的模型。`agents/at-pm.md` 的 `model: sonnet` 只对带 `--agent` 起的会话有效；
  命令行里项目经理不再默认是 `sonnet`，README 照实改。

## 7. 要实测的

1. 普通会话主线程的 hook 输入不带 `agent_type`，带会话 id。
2. `UserPromptExpansion` 上的回传与界面上那一行，在这五条命令上都到得了；模型经 `Skill` 工具调命令时不发这个事件。
3. `disable-model-invocation: true` 对插件命令生效。
4. `PreToolUse` 的 hook 拒得掉主线程的 `Skill`、`SendMessage`、`ListAgents`、`EnterWorktree`、`Workflow` 调用，
   模型拿到的是拒绝理由。逐个量。
5. 压缩、续会话之后会话 id 不变；`/clear`、分叉之后 id 变了。
6. 压缩之后，靠每轮的自检提醒，项目经理重新读了角色正文、照它做事。
7. 桌面应用里走一遍真实会话：新会话派 `Explore`、写项目文件都不被拦、对话里没有门禁的话 → 敲 `/poundlock:at <需求>` →
   自检在线 → 派 `at-product` → 中途压缩一次 → 项目经理仍然照角色正文做事。
8. 装着 superpowers、`Skill` 被拦的情形下，项目经理会不会先去头脑风暴。
9. 升级之前开的项目经理会话续上之后，身份还是 `at-pm`。

实测照仓库的规矩做：用探针会话，做完收尾；结果写进新的那份带日期记录。

## 8. 我的裁定

这些用户没说，是我定的，批准设计时请一并看：

1. **变身之后只拦绕得开门禁的那几样工具**（`Skill`、`SendMessage`、`ListAgents`、`EnterWorktree`、`Workflow`），
   MCP、网页、宿主应用的工具不拦（§5.5）。这是和今天差别最大的一处：项目经理从此看得了网页、用得了 MCP。
2. **触发变身的是五条干活的命令**，`/poundlock:at-status` 不触发；不另设一条专门的变身命令（§5.2）。
3. **没有变回普通会话的命令**（§5.2）。
4. **团队之外的人写不了 `.poundlock/` 下的任何东西**（`Edit` / `Write`），`.poundlock/` 之外不拦（§5.4）。
5. **普通会话不受微调认领的约束**：改到微调正在改的文件，门禁不拦也不记（§5.4）。
6. **团队之外的调用者一律派不了团队角色**，把今天放行的那条路关上（§5.4）。
7. **`at-pm` 这个 agent 定义和「带它起的会话就是项目经理」留着**；续上之后身份没恢复的，敲一次 `/poundlock:at-resume`，
   不加新的身份来源（§5.8）。
8. **没有会话 id 时当项目经理会话；记号文件读不出来时谁都不靠记号当项目经理**（§5.7，2026-11-28 修订）。
9. **每轮的自检提醒保留不走 node**，措辞改成有条件的；普通会话每轮多一行可以忽略的话（§5.3）。
10. **记号放在 `.poundlock/` 下**，命令展开时目录不在就建（§5.2）。
11. **六条命令都不让模型自己调**（`disable-model-invocation: true`），为它在 frontmatter 的受限写法里开第二个窄口（§5.2）。
12. **Claude Code 的下限抬到做这轮实测的版本**（§5.8）。
