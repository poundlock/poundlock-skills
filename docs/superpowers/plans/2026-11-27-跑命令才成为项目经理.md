# 跑命令才成为项目经理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 启用了插件的目录里，新开的会话是普通会话；用户敲一条团队命令，这个会话才成为项目经理会话，门禁从那一刻起按会话认它。

**Architecture:** 新的纯函数模块 `hooks/lib/pm-session.mjs` 定「记号」的格式、谁是团队之外的人、各处文案；`gate.mjs` 只做 I/O：一个新的记录器在命令展开时给会话记号，各道门禁在入口按身份分流（团队之外的人走一条不依赖运行上下文的新判定，项目经理与团队角色走原来的代码），一个新的检查项拦项目经理会话里绕得开门禁的工具。插件根的 `settings.json` 删掉，角色正文改由命令开头、门禁回传与每轮提醒指路去读。

**Tech Stack:** Node（`hooks/boot.mjs` 的 `MIN_NODE` 起），零 npm 依赖，`node --test`。

**Spec:** `docs/superpowers/specs/2026-11-27-跑命令才成为项目经理-design.md`

## Global Constraints

- 分支 `feat/pm-on-demand`。提交信息不加署名行。只 `git add` 这一任务点名的文件，不用 `git add -A`。
- 零 npm 依赖，不建 `package.json`；`hooks/` 下不用晚于 `MIN_NODE` 的内建。`hooks/boot.mjs` 与它读的 `hooks/lib/checks.mjs` 要能在 Node 12.17 上解析：`checks.mjs` 不 import 任何模块。
- 门禁子进程一律经 `tests/helpers/gate-runner.mjs` 的 `run` / `runAsync` 起。判据在仓库根裸跑 `node --test`，不带路径参数；偶发卡死或 `Unable to deserialize cloned data` 先重跑（仓库 `CLAUDE.md`「坑」）。
- 运行时读得到的文字（角色正文、命令、门禁回传与拒绝理由、hooks.json 里的提醒）只写现行规则：不写 docs 编号、里程碑、「上一版」。README 只写结论。
- 外部值进回传与拒绝理由：磁盘上的用 `quote`，这次调用给的参数与门禁拼出的路径用 `inline`；会话 id 不进文字。新拼一个外部值，`tests/trusted-echo.test.mjs` 的入口清单跟着补。
- JS 源码里要打出占位符字面时写成 `'$' + '{CLAUDE_PLUGIN_ROOT}'`，不放进模板串。特殊字符用 `String.fromCharCode`。落盘后扫控制字节与行尾（LF）。
- 两种判不出来方向相反（设计 §5.7，2026-11-28 修订）：hook 输入没有会话 id → 当项目经理会话，门禁照常拦；记号文件读不出来 → 谁都不靠记号当项目经理，不带 `agent_type` 的主线程按团队之外的人待。两个方向都不许反。
- 升级之前的状态不改判：带 `agent_type` 为 `poundlock:at-pm`、没有记号的主线程照旧是项目经理（设计 §5.8）。
- 发版：`.claude-plugin/plugin.json` 挪到 `9.2.0`，`CHANGELOG.md` 最上面加一行。推功能分支、CI 全绿之后才谈合 `main`；合 `main` 就是发布，由用户的会话定。

## Review Focus

1. 记号文件在项目经理会话跑着的时候没了（`git clean`、用户删了 `.poundlock/`）或被改坏：没了的、改坏的，这个会话下一次自检、派团队角色、写账本都被拒并拿到出路（改坏的理由里多一句原因）；用户重新敲命令，记录器把改坏的文件重建。普通会话不因为一份坏文件被拦。→ Task 1、Task 3 的判据。
2. hook 输入没有 `session_id`（旧 CLI、SDK 宿主）：当项目经理，行为与今天相同。→ Task 1、Task 3 的判据。
3. 两个会话几乎同时敲命令：两条记号都在。→ Task 2 的判据（`runAsync` 并行）。
4. 会话开在项目的子目录里、`.poundlock/` 在上层，或者哪里都还没有 `.poundlock/`：记号写进门禁认的那个项目根，之后门禁读的是同一份。→ Task 2 的判据。
5. 普通会话写 `.poundlock/` 的怪写法（大小写不同、`..` 穿越、经符号链接、不存在的子目录）：照样认成 `.poundlock/` 之下并拒。→ Task 1、Task 3 的判据。

## Rulings 预置（执行时照抄进 `docs/107`）

- **界面上那一行改由项目经理说。** 设计 §5.2 写「界面上一行固定的话」；`UserPromptExpansion` 上门禁的出口不发 `systemMessage`（`hooks/lib/fail-open.mjs` 的 `hookOutput` 的既有契约）。记录器发一段受信回传【身份】，命令开头叫项目经理照它对用户说一句。
- **`settings.json` 删掉，不留空对象。** 判据钉「文件不在」，免得有人把 `agent` 悄悄加回去。
- **带 `agent_type` 的会话敲命令不记号。** 那种会话的身份由 `agent_type` 定。
- **记号文件读不出来时记录器把它重建成只有这个会话的一份**（2026-11-28 改：原来定的是不覆盖）。读不出来时谁都不是项目经理（设计 §5.7），不重建就没有会话当得上；别的项目经理会话的记号已经随那份坏文件没了，它们下一次团队动作被拒、重新敲命令。stderr 留一行。
- **命令每次展开都发【身份】**，不只第一次：`/poundlock:at-resume` 正是压缩之后用的，那时要重新指到角色正文。「对用户说一句」只在第一次记号时带。
- **拦的工具清单写两份、判据对齐。** `checks.mjs` 被 `boot.mjs` 读，不能 import；`pm-session.mjs` 的 `BLOCKED_TOOLS` 是单一真源，`checks.mjs` 里那份字面量由判据钉成相等。
- **Task 0 量出某样工具 hook 拦不住，或者会话里根本没有它**：从 `BLOCKED_TOOLS` 去掉，在 `docs/00-开放边界.md` 记一行。量出普通会话主线程的 hook 输入带 `agent_type` 或不带 `session_id`：停下，回报用户，设计的前提不成立。

### Task 1: `pm-session.mjs` 纯函数与门禁专属文件登记

**Files:**
- Create: `hooks/lib/pm-session.mjs`
- Modify: `hooks/lib/control-files.mjs`（`PROJECT_GATE_FILES` 一带）
- Test: `tests/pm-session.test.mjs`（新）、`tests/control-files.test.mjs`

**Interfaces:**
- Consumes: `hooks/lib/decide.mjs` 的 `PLUGIN_PREFIX`、`stripPluginPrefix`、`malformedCaller`、`isValidRoster`、项目经理的裸名常量（没导出就导出为 `PM_ROLE`）；`path-norm.mjs` 的 `norm`；`trusted.mjs` 的 `inline`；`text-norm.mjs` 的 `normalizeText`。
- Produces:

```js
// control-files.mjs
export const PM_SESSIONS_FILE = 'pm-sessions.json'   // 并进 PROJECT_GATE_FILES

// pm-session.mjs
export const MARK_COMMANDS = ['at', 'at-tweak', 'at-resume', 'at-init', 'at-skills']
export const BLOCKED_TOOLS = ['Skill', 'SendMessage', 'ListAgents', 'EnterWorktree', 'Workflow']
export const NOT_PM_HEAD = 'poundlock：这个会话不是项目经理会话'
export const OUTSIDE_HEAD = 'poundlock：这次调用来自团队之外'
export const IDENTITY_TAG = '【身份】'
export function readMarks(bytes)            // null/undefined → { ok: true, sessions: {} }；合法 → { ok: true, sessions }；其余 → { ok: false }
export function withMark(marks, sessionId, { at, command })   // → 新的 marks；已经记过 → null
export function marksText(marks)            // → 两格缩进的 JSON 加一个换行，形如 { "sessions": { "<id>": { "at", "command" } } }
export function markOf(input)               // → { sessionId, command } | null
export function standingOf({ input, roster, marks })
  // → { outsider: boolean, pm: boolean, kind: null | 'unmarked' | 'replaced' | 'subagent', unjudged: null | 'no-session-id' | 'marks-unreadable' }
export function inPoundlock(filePath)       // → boolean
export function outsiderReason({ kind, action, target })   // action: 'dispatch' | 'write' | 'self-check'
export function unjudgedNote(unjudged)      // null → ''
export function blockedToolReason(toolName)
export function identityNotice({ pluginRoot, first })      // 以 IDENTITY_TAG 打头
export function roleFileNote({ pluginRoot })
```

`standingOf` 的判定（设计 §5.1、§5.7），按顺序；回的对象四个键都在，下面没写出的键是 `false`（`outsider`、`pm`）或 `null`（`kind`、`unjudged`）：

1. `malformedCaller(input)` 或花名册不合法 → `{ outsider: false, pm: false }`（交给原来的代码去拒）。
2. `agent_type` 缺失或为 `null`：带非空 `agent_id` → `{ outsider: false, pm: false }`；`session_id` 不是非空字符串 → 项目经理，`unjudged: 'no-session-id'`；`marks.ok` 为假 → 团队之外，`kind: 'unmarked'`、`unjudged: 'marks-unreadable'`；`marks.sessions` 有这个 id（own key）→ 项目经理；否则 → 团队之外，`kind: 'unmarked'`。
3. `agent_type` 是字符串，剥掉插件前缀：是项目经理的裸名 → `pm` 为「不带 `agent_id`」；是花名册的 own key → `{ outsider: false, pm: false }`；否则 → 团队之外，带 `agent_id` 是 `'subagent'`，不带是 `'replaced'`。

`markOf`：`expansion_type === 'slash_command'`、`command_name` 以 `PLUGIN_PREFIX` 打头且剥掉之后在 `MARK_COMMANDS` 里、`session_id` 是非空字符串、`agent_type` 缺失或为 `null`，四条都成立才回对象。

`inPoundlock`：字面路径（`resolve` 后按本平台分隔符切）与物理路径（`norm`）任一有一段**规范化之后**等于 `.poundlock` 就是真（与 `gate-check.mjs` 的 `isGateCheck` 同一个「字面与物理任一命中」）。段的规范化：截掉第一个冒号及之后的部分（流后缀），去掉结尾的点与空格，转小写；各平台都做（设计 §5.4，2026-11-28 补）。

文案要点（措辞自定，判据只钉下面断言里的东西）：`outsiderReason` 在 `kind` 为 `'unmarked'` 时以 `NOT_PM_HEAD` 打头，另两种以 `OUTSIDE_HEAD` 打头；`'unmarked'` 的结尾给出路——请用户自己在这个会话里敲 `/poundlock:at <需求>`（或另外四条），模型自己调不了；用户已经敲过还看到这一句，可能是 Claude Code 太旧或记号文件被删了，请用户再敲一次。`'subagent'` 的结尾叫它回报派它的人。`action` 为 `'self-check'` 时说门禁在跑、但只对项目经理会话回答在线。`blockedToolReason('Skill')` 提到 `/poundlock:at-skills`。`identityNotice` 与 `roleFileNote` 给出角色正文的绝对路径 `<pluginRoot>/agents/at-pm.md`、说明文件里的占位符 `CLAUDE_PLUGIN_ROOT` 指的就是 `<pluginRoot>`、眼前没有全文就先读；`first` 为真时多一句「对用户说一句：这个会话从现在起是项目经理会话，到会话结束或 `/clear` 为止」。

```js
import { test } from 'node:test'
import assert from 'node:assert/strict'
import { readFileSync } from 'node:fs'
import {
  BLOCKED_TOOLS, IDENTITY_TAG, MARK_COMMANDS, NOT_PM_HEAD, OUTSIDE_HEAD,
  blockedToolReason, identityNotice, inPoundlock, markOf, marksText, outsiderReason, readMarks, roleFileNote, standingOf, withMark,
} from '../hooks/lib/pm-session.mjs'
import { GATE_CHECK_ONLINE } from '../hooks/lib/gate-check.mjs'
import { isGateFile, PM_SESSIONS_FILE } from '../hooks/lib/control-files.mjs'

const roster = JSON.parse(readFileSync(new URL('../roster.json', import.meta.url), 'utf8'))
const main = (over = {}) => ({ session_id: 's-1', ...over })
const marks = (...ids) => ({ ok: true, sessions: Object.fromEntries(ids.map((id) => [id, { at: 't', command: 'at' }])) })
const S = (input, m = marks()) => standingOf({ input, roster, marks: m })
const PM = { outsider: false, pm: true, kind: null, unjudged: null }
const LEGACY = { outsider: false, pm: false, kind: null, unjudged: null }

test('不带 agent_type 的主线程：记过号是项目经理，没记过是团队之外的人', () => {
  assert.deepEqual(S(main(), marks('s-1')), PM)
  assert.deepEqual(S(main(), marks('s-2')), { outsider: true, pm: false, kind: 'unmarked', unjudged: null })
  // 会话 id 撞上原型链上的名字时不算记过
  assert.deepEqual(S(main({ session_id: 'constructor' }), marks()), { outsider: true, pm: false, kind: 'unmarked', unjudged: null })
})

test('没有会话 id 当项目经理；记号文件读不出来谁都不靠记号当项目经理', () => {
  assert.deepEqual(S({}), { ...PM, unjudged: 'no-session-id' })
  assert.deepEqual(S(main({ session_id: '' })), { ...PM, unjudged: 'no-session-id' })
  assert.deepEqual(S(main(), { ok: false }), { outsider: true, pm: false, kind: 'unmarked', unjudged: 'marks-unreadable' })
  // 带 at-pm 身份的不看记号
  assert.deepEqual(S(main({ agent_type: 'poundlock:at-pm' }), { ok: false }), PM)
})

test('上一版的状态：带 at-pm 身份的主线程没有记号也是项目经理', () => {
  assert.deepEqual(S(main({ agent_type: 'poundlock:at-pm' })), PM)
  assert.deepEqual(S(main({ agent_type: 'at-pm' })), PM)
})

test('被换掉的主会话、花名册外的子代理是团队之外的人；团队角色与认不出的调用者交给原来的代码', () => {
  assert.deepEqual(S(main({ agent_type: 'general-purpose' })), { outsider: true, pm: false, kind: 'replaced', unjudged: null })
  assert.deepEqual(S(main({ agent_type: 'Explore', agent_id: 'a1' })), { outsider: true, pm: false, kind: 'subagent', unjudged: null })
  assert.deepEqual(S(main({ agent_type: 'other:at-backend', agent_id: 'a1' })), { outsider: true, pm: false, kind: 'subagent', unjudged: null })
  assert.deepEqual(S(main({ agent_type: 'poundlock:at-backend', agent_id: 'a1' })), LEGACY)
  assert.deepEqual(S(main({ agent_type: 'poundlock:at-architect' })), LEGACY)
  assert.deepEqual(S(main({ agent_type: 'poundlock:at-pm', agent_id: 'a1' })), LEGACY)
  assert.deepEqual(S(main({ agent_type: 42 })), LEGACY)
  assert.deepEqual(standingOf({ input: main(), roster: {}, marks: marks() }), LEGACY)
})

test('记号文件：不在是一个项目经理会话都没有，读不懂是读不出来', () => {
  assert.deepEqual(readMarks(null), { ok: true, sessions: {} })
  assert.deepEqual(readMarks(marksText(marks('s-1'))), marks('s-1'))
  for (const bad of ['', 'x', '[]', 'null', '{"sessions":[]}', '{}']) assert.deepEqual(readMarks(bad), { ok: false }, bad)
  assert.equal(marksText(marks('s-1')), '{\n  "sessions": {\n    "s-1": {\n      "at": "t",\n      "command": "at"\n    }\n  }\n}\n')
  assert.equal(withMark(marks('s-1'), 's-1', { at: 't2', command: 'at-init' }), null)
  assert.deepEqual(Object.keys(withMark(marks('s-1'), 's-2', { at: 't2', command: 'at-init' }).sessions), ['s-1', 's-2'])
})

test('记号只认用户敲的五条命令、不带身份的会话', () => {
  const e = (command_name, over = {}) => ({ expansion_type: 'slash_command', command_name, session_id: 's-1', ...over })
  for (const c of MARK_COMMANDS) assert.deepEqual(markOf(e(`poundlock:${c}`)), { sessionId: 's-1', command: c })
  for (const input of [e('poundlock:at-status'), e('at'), e('other:at'), e('poundlock:at', { expansion_type: 'skill' }), e('poundlock:at', { session_id: '' }), e('poundlock:at', { agent_type: 'poundlock:at-pm' })]) {
    assert.equal(markOf(input), null, JSON.stringify(input))
  }
})

test('.poundlock 之下：按路径形状认，大小写、穿越都认', () => {
  for (const p of ['/p/.poundlock/x', '/p/.POUNDLOCK/runs/r/state.json', '/p/a/../.poundlock/x', '/p/.poundlock']) assert.equal(inPoundlock(p), true, p)
  // Windows 上指向同一个目录的写法：结尾的点与空格、流后缀
  for (const p of ['/p/.poundlock./x', '/p/.poundlock /x', '/p/.poundlock.. /x', '/p/.poundlock::$INDEX_ALLOCATION/x', '/p/.poundlock:s/x', '/p/.PoundLock./x']) assert.equal(inPoundlock(p), true, p)
  for (const p of ['/p/src/x', '/p/src/.poundlock.md', '/p/.poundlocks/x', '/p/x.poundlock/y', '', undefined]) assert.equal(inPoundlock(p), false, String(p))
})

test('文案：打头的固定串、出路、自检那一支不带在线', () => {
  const r = (kind, action, target) => outsiderReason({ kind, action, target })
  assert.ok(r('unmarked', 'dispatch', 'at-backend').startsWith(NOT_PM_HEAD))
  assert.match(r('unmarked', 'dispatch', 'at-backend'), /\/poundlock:at /)
  assert.ok(r('subagent', 'write').startsWith(OUTSIDE_HEAD))
  assert.ok(r('replaced', 'write').startsWith(OUTSIDE_HEAD))
  for (const kind of ['unmarked', 'replaced', 'subagent']) assert.ok(!r(kind, 'self-check').includes(GATE_CHECK_ONLINE), kind)
  assert.match(blockedToolReason('Skill'), /\/poundlock:at-skills/)
  for (const t of BLOCKED_TOOLS) assert.ok(blockedToolReason(t).includes(t), t)
  const first = identityNotice({ pluginRoot: '/plug', first: true })
  assert.ok(first.startsWith(IDENTITY_TAG))
  assert.match(first, /\/plug\/agents\/at-pm\.md/)
  assert.match(first, /CLAUDE_PLUGIN_ROOT/)
```
